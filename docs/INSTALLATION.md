# 설치와 완전 제거

macOS에서 릴리스 ZIP의 압축을 풀고 `install.command`를 더블클릭하면 고정 버전 확장 파일을 사용자 전용 설치 폴더에 준비하고 Chrome 확장 관리 화면을 엽니다. 릴리스에는 실행 의존성이 포함되므로 Node.js·npm·네이티브 FFmpeg를 별도로 설치하지 않습니다. Linux에서는 `bash scripts/install.sh`를 실행합니다.

일반 macOS Chrome은 웹 스토어 밖의 확장을 스크립트로 무인 설치할 수 없습니다. 설치 창을 여는 동작은 한 번에 실행되지만, **Chrome에서 개발자 모드를 켜고 ‘압축해제된 확장 프로그램을 로드합니다’를 눌러 폴더를 선택하는 사용자 동작은 필요합니다.** 이 스크립트는 Chrome 정책이나 프로필 설정을 변경하지 않습니다. [Chrome 설치 정책](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions), [unpacked 설치 방법](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)

## 설치 위치

- macOS: `~/Library/Application Support/Video Grabber/extension`
- Linux: `~/.local/share/video-grabber/extension`

macOS 설치 스크립트는 위 경로를 클립보드에 복사하고 Finder에서도 폴더를 엽니다. 관리 폴더 안에는 확장 파일, 제거 스크립트, 해당 설치의 캐시와 간단한 설치 로그만 보관합니다. `SHA256SUMS`가 포함된 릴리스는 설치 전에 파일 해시를 검사합니다. 기존 설치가 있으면 준비 완료 후 교체하며, Chrome의 확장 새로고침 버튼으로 업데이트를 적용합니다.

소스 저장소에서 실행하면 `npm ci --ignore-scripts`와 `npm run build`를 실행합니다. 이 경로에만 Node.js 22 이상과 npm이 필요합니다. 설치 스크립트가 전역 도구를 설치하지는 않습니다. 두 npm 명령과 빌드에서 실행하는 npm 하위 프로세스의 캐시·디버그 로그는 모두 관리 설치 폴더의 `cache/npm` 안에 둡니다. 생성한 소스 의존성·빌드 산출물의 위치는 `source-roots.txt`에 누적 기록합니다. 다른 체크아웃에서 다시 설치하거나 릴리스 ZIP으로 업데이트해도 이전 소스 위치를 유지하며, 같은 위치는 한 번만 기록합니다. 이전 버전의 `source-root.txt` 기록도 읽어 새 형식으로 유지합니다.

업데이트 빌드가 실패해도 기존 확장 파일은 유지되며, 시도한 소스 경로는 기존 설치의 제거 기록에 남겨 생성된 의존성·산출물까지 정리할 수 있습니다. 첫 설치가 실패하면 임시 설치 폴더와 npm 캐시·로그를 자동 정리합니다. 소스에 남은 빌드 산출물과 소유 표시는 해당 소스의 `uninstall.command`로 제거할 수 있습니다.

설치·업데이트·제거는 사용자마다 한 번에 하나만 실행됩니다. 같은 설치 경로뿐 아니라 같은 체크아웃을 공유하는 여러 설치의 빌드·정리가 충돌하지 않도록, 시스템 임시 폴더의 `.video-grabber-operation-<UID>.lock` 디렉터리를 원자적으로 생성해 잠급니다. 다른 작업이 실행 중이면 새 작업은 파일을 변경하지 않고 종료하므로 기존 작업이 끝난 뒤 다시 실행하세요. 정상 종료와 일반 오류·중단에서는 실행 중인 하위 명령과 파일 복구가 끝난 후 잠금 파일과 폴더를 제거합니다.

설치 화면을 여는 브라우저 프로세스는 빌드·파일 정리 작업과 분리합니다. Chrome이 계속 실행 중이어도 설치 스크립트는 종료하고 잠금을 해제하므로, 업데이트나 제거를 시작하기 위해 브라우저 전체를 닫을 필요는 없습니다. 제거할 때 Chrome의 확장 제거 확인과 터미널의 `REMOVE` 입력은 그대로 필요합니다.

`SIGKILL`이나 전원 중단으로 잠금이 남으면 자동으로 지우지 않습니다. 오류에 표시된 PID는 종료 여부를 확인할 단서이며, 다른 프로세스에 재사용되었을 수도 있습니다. 관련 설치·제거와 npm 빌드 프로세스가 모두 끝났는지 확인한 뒤, 표시된 잠금 폴더의 `pid`, `token` 두 파일만 지우고 빈 폴더를 `rmdir`로 제거한 다음 다시 실행하세요. 예상하지 못한 파일이나 심볼릭 링크가 있으면 그대로 두고 원인을 확인하세요. 실행 중인 작업의 잠금을 지우면 안 됩니다.

강제 종료로 설치 경로의 상위 폴더에 `.video-grabber-stage.*` 임시 폴더나 `.video-grabber-backup.*` 복구본이 남을 수도 있습니다. 해당 작업이 끝났음을 확인하고 `.video-grabber-owned` 소유 표시를 검증한 뒤 임시 폴더를 정리하세요. 복구본의 `installation` 폴더에는 이전 확장 파일이 있으므로 정상 설치나 복구를 확인하기 전에 삭제하지 마세요. 외부 프로그램이 설치 경로를 동시에 바꾼 경우에도 스크립트는 게시 실패를 표시하고 이전 복구본을 보존합니다.

## 제거

릴리스나 관리 설치 폴더의 `uninstall.command`를 더블클릭합니다. Linux에서는 `bash scripts/uninstall.sh`를 실행합니다.

1. 스크립트가 여는 제거 화면에서 **Chrome의 확장 제거 확인**까지 완료합니다. 지원되는 패키지는 전용 제거 화면으로 이동하며, 그렇지 않으면 `chrome://extensions`에서 Video Grabber를 제거합니다. 이 단계가 브라우저가 관리하는 IndexedDB 응답 데이터와 확장 설정을 정리합니다.
2. 터미널에 `REMOVE`를 입력하면 아래 로컬 산출물을 삭제합니다. 취소하거나 표준 입력이 없는 환경에서는 파일을 먼저 삭제하지 않습니다.

삭제 대상:

- 관리 설치 폴더 전체: 확장, 로컬 의존성, 제거 스크립트, 캐시, 로그
- 설치 스크립트가 기록한 **모든 소스 폴더**의 `node_modules`, `dist`, `artifacts`, `fixtures/media`, `.cache`, `.logs`
- 자신의 소스 저장소에서 실행한 제거 스크립트는 기록된 다른 소스 폴더와 함께 실행한 체크아웃의 이전 빌드 산출물도 정리
- 소스 폴더의 생성된 소유 표시 `.video-grabber-build-root`

소스 코드·`.git`·사용자가 저장한 영상 파일·다운로드한 원본 ZIP은 보존합니다. 시스템 Node.js, Chrome, 공유 npm 캐시 또는 다른 프로젝트의 의존성도 삭제하지 않습니다. 이 프로그램이 설치한 전역 의존성은 없습니다. 다운로드한 ZIP/압축을 푼 원본 배포 폴더 자체도 없애려면 Finder에서 해당 다운로드 항목을 삭제하세요.

소유 표시가 다른 폴더나 심볼릭 링크를 경유하는 삭제 경로는 거부합니다. 같은 체크아웃에서 여러 관리 폴더에 설치했을 때, 먼저 제거한 설치가 소스의 산출물과 소유 표시를 모두 지웠다면 나머지 설치도 제거하거나 업데이트할 수 있습니다. 이때 소유 표시와 위 삭제 대상이 **전부 없는 경우에만** 이미 정리된 소스로 취급하며, 소유 표시 없이 산출물이 남아 있으면 거부합니다. 기록된 모든 소스와 삭제 대상을 먼저 검사하며, 하나라도 올바르지 않으면 파일 삭제를 시작하지 않습니다. 이미 존재하지 않는 소스 폴더는 건너뜁니다. 제거를 반복 실행해도 이미 제거된 관리 폴더로 인해 실패하지 않습니다.

## 자동 검증 및 직접 지정

브라우저를 열지 않고 파일 준비만 하려면 `--no-open`을 사용합니다. 설치 완료를 뜻하지는 않습니다.

```sh
bash scripts/install.sh --no-open
```

브라우저에서 이미 제거했다면 다음과 같이 파일 정리만 실행할 수 있습니다. **`--browser-removed`는 Chrome 데이터가 제거됐다는 실행자의 명시적 확인이며, 브라우저 제거를 대신하지 않습니다.**

```sh
bash scripts/uninstall.sh --no-open --browser-removed
```

테스트나 별도 관리 폴더에는 `--target-root /absolute/path/video-grabber`를 사용할 수 있습니다. 경로의 마지막 폴더 이름은 `video-grabber` 또는 `Video Grabber`여야 하며, 기존 폴더에는 일치하는 소유 표시가 있어야 합니다. 소스에서 설치할 때는 빌드가 기존 설치를 지우지 않도록 **소스 체크아웃 밖의 경로**만 허용합니다. 다른 관리 설치의 안쪽이나 관리 설치를 포함하는 경로, 이미 소유 표시가 있는 다른 소스 체크아웃 안에는 설치할 수 없습니다. 소스 산출물 안에 관리 설치가 남아 있으면 빌드와 제거도 중단합니다. 이전 버전 등에서 중첩된 설치가 있다면 안쪽부터 제거해야 합니다. 자동 테스트는 임시 디렉터리에서만 설치와 제거를 실행합니다.

자동 검증은 `VIDEO_GRABBER_LOCK_ROOT`에 현재 사용자가 소유한 별도 임시 폴더를 지정하여 잠금도 격리합니다. 이는 테스트용 옵션이며, 실제 설치 명령끼리 다른 값을 사용하면 서로 잠금을 공유하지 못하므로 일반 사용에서는 설정하지 마세요.
